    Getting started¶

    This section takes you from nothing to a first synced table. You install AlgoBridge, create the first admin, connect both ends of the sync pair, and watch the first records arrive.

    What AlgoBridge is¶

    AlgoBridge is open-source, self-hosted Salesforce sync, with no licence fee and no per-row charge. It keeps a Salesforce org and a PostgreSQL database in sync in both directions:

    • Salesforce to PostgreSQL. AlgoBridge learns which objects changed, either by polling with SOQL on a schedule or from the optional change notifier in your org, then fetches the changed records and upserts them into PostgreSQL tables it creates and owns.
    • PostgreSQL to Salesforce. For mappings you make read-write, a row-level trigger captures every INSERT, UPDATE and DELETE into a change log table, and AlgoBridge sends the changes to Salesforce in batches.

    A few properties shape how you deploy it:

    Property What it means for you
    One container image The same image serves the console and runs the sync work. APP_ROLE decides which a container does.
    Single tenant You run your own instance, on your own infrastructure, with your own data. There is no hosted service.
    One sync pair per instance An instance syncs exactly one Salesforce org with one PostgreSQL database. For another pair, run another instance.
    PostgreSQL only Jobs, sessions and all state live in PostgreSQL. There is no Redis, broker or external queue.
    Counts against your API limits Like any integration you run yourself, AlgoBridge spends your org's API requests. Every read and write is batched, and polling slows down or pauses on its own as the org nears its limit. See API budget.

    AlgoBridge does not use Salesforce Change Data Capture or any streaming API.

    What you need¶

    Before you start, have these ready:

    You need Why Notes
    A long-lived container runtime Runs the AlgoBridge image. Docker Compose, Kubernetes, or any platform that keeps a container running. The worker must stay on: scale-to-zero platforms need a minimum of one instance.
    PostgreSQL 15 or later, for AlgoBridge itself The platform database: users, connections, mappings, jobs and sync state. Set as DATABASE_URL. The reference Compose file runs one for you.
    A PostgreSQL database for your application data The client database: the tables AlgoBridge syncs. Must be a different database from the platform database. They may share a server. AlgoBridge refuses to connect its own database as the client database.
    A Salesforce org and an External Client App in it AlgoBridge signs in to the org through this app with OAuth. You create the app in Salesforce Setup during your first sync. A dedicated integration user is recommended.
    Outbound HTTPS AlgoBridge calls Salesforce's APIs. Inbound HTTPS from Salesforce is only needed for the optional change notifier.
    A public address for the console Sign-in redirects and the Salesforce callback are built from it. Set as PUBLIC_URL. It must be https:// unless the host is localhost. Terminate TLS at your reverse proxy or platform.

    Two databases, always

    AlgoBridge keeps its own data and your data apart. The platform database holds the algobridge_jobs schema and the algobridge_migrations table. The client database holds your mapped tables, the capture triggers and the algobridge_change_log table. No transaction ever spans both.

    The path to a first sync¶

    1. Install AlgoBridge. Start the image and its platform database with Docker Compose, set PUBLIC_URL and ENCRYPTION_KEY, and check that /readyz answers.
    2. Create the first admin. Run create-admin, open the set-password link it prints, and sign in.
    3. Connect both ends. On the Connections screen, connect your client database and your Salesforce org.
    4. Add a mapping and provision it. Choose a Salesforce object, choose its fields, then click Create table. AlgoBridge creates the table in PostgreSQL and starts the initial load.
    5. Watch it sync. Follow the initial load on the mapping's Load panel and in the Live log.

    When the first sync works, the configuration reference lists every environment variable the app reads.
