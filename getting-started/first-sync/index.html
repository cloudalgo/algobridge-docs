    Run your first sync¶

    In this page you connect your PostgreSQL database and your Salesforce org, map one Salesforce object to a table, and watch its records load. It follows the console's own screens in the order they ask for things.

    You need a running instance with ENCRYPTION_KEY set and an admin who can sign in. If you don't have that yet, install AlgoBridge first.

    Until both ends are connected, the Overview page reads Connect both ends of the pair, and the top bar shows each end as not connected. Both steps below happen on Connections, under Instance in the sidebar. Only admins see it.

    Open the first sync steps full size

    1. Connect the client database¶

    The client database is your application's PostgreSQL database: the one AlgoBridge creates tables in and syncs. It must not be AlgoBridge's own platform database.

    1. Open Connections. The PostgreSQL panel reads Not connected.

    2. Paste one connection URL into Connection URL, for example:

      postgres://app_user:change-me@db.example.com:5432/app?sslmode=require

    3. Click Test and connect.

    AlgoBridge connects with a 5-second timeout and runs SELECT version() before saving anything. If the test fails, nothing is saved, and the error never shows the password. Once connected, the panel lists the host, port, database, user, SSL mode and server version. The URL itself is stored encrypted and never shown again.

    The URL accepts one option, sslmode (disable, allow, prefer, require, verify-ca or verify-full). Without it the driver's default applies, which does not use SSL. Use require or verify-full for any database reached over a network.

    Set it from the deployment instead

    You can set CLIENT_DATABASE_URL on every container instead of using this screen. It then wins over the screen, which shows the connection as Set by the deployment (CLIENT_DATABASE_URL). See Client database for the trade-offs.

    What the database role needs¶

    AlgoBridge runs every statement in your database itself; there is no "copy this SQL to your DBA" path. Before it creates anything, it checks that the role in the URL can:

    • create the hstore extension, or find it already installed;
    • own the target schema (algobridge by default), or create it.

    On the first provisioning, the target schema must also be empty. When a check fails, the mapping's Apply panel names the missing grant instead of showing a raw PostgreSQL error.

    2. Connect Salesforce¶

    AlgoBridge signs in to your org through an External Client App that you create in Salesforce, using OAuth with PKCE. It then acts as the Salesforce user who authorizes it. Use a dedicated integration user, so AlgoBridge's API calls and permissions stay separate from people's.

    Create the External Client App¶

    1. On Connections, find the Salesforce panel and click Copy next to the callback URL. It is your PUBLIC_URL followed by /connections/salesforce/callback, for example:

      https://sync.example.com/connections/salesforce/callback

    2. In Salesforce Setup, open External Client App Manager and create a new app. Give it a name and a contact email.

    3. Turn on Enable OAuth and paste the callback URL as the Callback URL.
    4. Add the OAuth scopes Manage user data via APIs (api) and Perform requests at any time (refresh_token, offline_access).
    5. Turn on Require Proof Key for Code Exchange (PKCE), and leave Require secret for Web Server Flow on.
    6. In the app's policies, set Refresh Token Policy to keep the token valid until revoked, or allow refresh token rotation.
    7. Save, then open Consumer Key and Secret and copy both. A new app can take a few minutes to become usable.

    Give AlgoBridge the credentials and connect¶

    1. Back on Connections, paste the Consumer key and Consumer secret and click Save app credentials. The secret is stored encrypted and never shown again.
    2. Enter the org's My Domain URL, such as https://yourcompany.my.salesforce.com. A sandbox looks like https://yourcompany--sandbox.sandbox.my.salesforce.com. Only hosts ending in .my.salesforce.com are accepted.
    3. Click Connect to Salesforce. Salesforce opens.
    4. Sign in as the integration user and allow access.

    Salesforce sends you back to Connections, which now shows the org, the user AlgoBridge is authorized as, and the org's API usage today.

    If Salesforce shows an error
    What you see What to do
    redirect_uri_mismatch The app's Callback URL does not match the instance's. Copy it again from Connections, including https and with no trailing slash, and check PUBLIC_URL.
    The consumer key or secret was rejected Replace the credentials on Connections.
    The app must allow the refresh_token scope Add the scope to the app, wait a few minutes, and connect again.
    The connect link expired More than 10 minutes passed, or the link was already used. Click Connect to Salesforce again.

    More cases are in Salesforce connection.

    You can also supply the app's credentials as SALESFORCE_CLIENT_ID and SALESFORCE_CLIENT_SECRET. When both are set they win over the screen.

    3. Pick a change source¶

    The change source decides how AlgoBridge learns that Salesforce records changed. Fetching the changed records costs the same whichever you pick; the source decides what it costs to find out. Choose it on Connections, in the Change detection panel.

    Source Installs in your org Cost to learn about changes
    Composite polling (default) Nothing. One API request per five objects per poll.
    Apex probe The AlgoBridge Apex bundle: one read-only class, its tests and a permission set. One API request per poll for up to 90 objects.
    Change notifier The same bundle, a one-time pairing, and two Flows per synced object. Needs AlgoBridge reachable from Salesforce over HTTPS. Zero, plus one fallback poll an hour.

    For a first sync, keep Composite polling. It needs nothing installed, and you can switch later without touching your mappings.

    To use the Apex probe instead:

    1. In Change detection, click Deploy bundle. The deploy runs in the background and the panel shows Deploy succeeded or Deploy failed. The integration user needs Modify All Data (or Modify Metadata Through Metadata API Functions) and Author Apex to deploy.
    2. In Salesforce Setup, assign the AlgoBridge Integration permission set (algobridge_Integration) to the integration user, and to no one else.
    3. Click Use this source on the Apex probe card. AlgoBridge makes one status call to the bundle and saves your choice only if the bundle answers.

    The change notifier takes a few more steps. See Change sources and Apex bundle.

    4. Add a mapping¶

    A mapping says which Salesforce object syncs into which PostgreSQL table, with which fields. Members and admins can create mappings.

    Check the instance settings first¶

    Open Mappings, under Sync in the sidebar. The Settings panel holds two instance-wide choices:

    • Target schema: the PostgreSQL schema AlgoBridge creates its tables in. The default is algobridge. You can change it only until the first mapping exists.
    • Write algorithm: how changes are sent to Salesforce. Ordered Writes (recommended) is the default. Merged Writes merges several changes to one record before sending, and reorders parents ahead of children. You can change it at any time.

    Choose the object¶

    1. Click New mapping. The first step, Choose object, lists the objects in your org.
    2. Search for the object, for example Account, and click Choose. Click Refresh if a new object is missing from the list.

    Choose fields and settings¶

    The second step, Choose fields and settings, opens the editor. The table name comes from the object's API name, lowercased, and is fixed once the mapping exists.

    Panel What to choose
    Direction Read-only: Salesforce changes sync to PostgreSQL, and PostgreSQL never writes back. Read-write: changes sync both ways. Read-write is unavailable for objects Salesforce reports as neither createable nor updateable.
    When both sides change Read-write only. Salesforce wins (the default), PostgreSQL wins, or Latest change wins. See Conflicts.
    Matching key An optional External ID field, chosen from fields that are External ID and Unique in Salesforce. Without one, rows inserted in PostgreSQL risk creating duplicates.
    Polling Fastest and Slowest poll intervals in minutes: 5 and 30 by default, each between 2 and 60. The interval stretches toward the slowest while nothing changes, and snaps back to the fastest when something does.
    Fields Tick the fields to sync. Id (stored as sfid) and SystemModstamp are always included, and so is IsDeleted when the object has it. CreatedDate and Name start ticked. Formula fields are listed but disabled, tagged Formula field — not synced.
    Reference fields Optional. Lets a child row point at its parent by the parent's External ID, for records created in PostgreSQL.

    Each field becomes a column named after its API name, lowercased. Anything that blocks saving is listed under Problems and warnings.

    Click Create mapping. The mapping is saved as a Draft: nothing exists in PostgreSQL yet, and nothing syncs.

    Start small

    For a first sync, pick an object with a modest number of records, make it Read-only, and tick only the fields you need. You can add fields later; adding a field adds its column and loads only that column.

    5. Provision the table¶

    Provisioning makes your client database match the saved mapping. It runs only when you click it.

    1. On the mapping's page, find the Apply panel. For a new mapping it reads Nothing exists in PostgreSQL for this mapping yet and lists the statements it will run.
    2. Read the statements, then click Create table.

    A worker runs the plan in one transaction: if any statement fails, none of them stick, and the panel shows the failing statement. The mapping shows Provisioning while it runs, then Active.

    For a read-only mapping, AlgoBridge creates:

    • the hstore extension, if it is missing;
    • the table, with sfid and one column per mapped field;
    • a unique index on sfid, a unique index on the External ID column if you chose one, and an index on each field you marked Indexed.

    A read-write mapping also gets the algobridge_lastop and algobridge_err status columns, the algobridge_capture trigger on the table, and, once per schema, the algobridge_change_log table and the algobridge_capture_change() trigger function.

    AlgoBridge never drops or recreates a table to apply a change. Later edits are applied the same way: save, read the pending statements on the Apply panel, then click Apply changes.

    6. Watch the initial load¶

    When a mapping first becomes active, AlgoBridge reads the whole object into the table. This is the initial load.

    1. AlgoBridge counts the object's records with one SELECT COUNT() query, then picks the cheaper transport: REST paging costs about one API call per 2,000 records; a Bulk API 2.0 query costs about five calls plus one per 50,000 records. Small objects go over REST and large ones over Bulk. If the org refuses Bulk, the load falls back to REST.
    2. The mapping's Load panel shows the load's kind (Initial load), its transport, its status and how far it has read. The Mappings list shows the same progress, for example Loading 42%.
    3. When the status reads Completed, the table holds the object's records, and normal polling takes over from the moment the load started.

    If the org's API usage is near its limit, the load waits and shows Waiting for API budget rather than spending calls it cannot afford. Stop load ends a running load and keeps what it has read; Reload starts again from an empty table.

    Check the result in your database:

    SELECT count(*) FROM algobridge.account;

    Replace algobridge with your target schema and account with your table name.

    Follow it in the Live log¶

    Open Live log, under Instance in the sidebar. It streams every process's log lines to your browser as they happen, so you can watch the load's Salesforce calls and PostgreSQL writes.

    • Filter by Level (Error, Warn, Info, Debug) and by Source (Worker, Queue, SOQL, Salesforce, PostgreSQL, Web), or pick one process or one mapping.
    • While anyone has the Live log open, every process also forwards its debug lines, such as each SOQL query. Your container logs on stdout are unaffected.
    • The Live log keeps no history: lines from before you opened it are not shown. Up to five people can watch at once. Only admins can open it.

    See Live log for more.

    7. Make a change and see it arrive¶

    Edit one of the synced records in Salesforce. Within one poll interval of the mapping (5 minutes by default, or longer if the interval has stretched), the change appears in the PostgreSQL row. Each pass is listed on the Activity page.

    For a read-write mapping, update a row in PostgreSQL instead. The capture trigger records it in algobridge_change_log, and AlgoBridge sends it to Salesforce in its next batch: when 200 changes are waiting, or the oldest has waited 60 seconds. The row's algobridge_lastop column shows PENDING until the send settles it.

    TRUNCATE is not synced

    The capture trigger fires on INSERT, UPDATE and DELETE, row by row. A TRUNCATE changes no row as far as the trigger is concerned, so nothing is deleted in Salesforce. Use DELETE FROM <table> to remove records on both sides.
