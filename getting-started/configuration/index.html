    Configuration reference¶

    This page lists every environment variable AlgoBridge reads, with its default and what it does. Use it when you write your Compose file, Kubernetes manifest or platform config.

    AlgoBridge reads its configuration only from environment variables. It never calls a secrets-manager API: if your secrets live in one, have your platform inject them as environment variables.

    How configuration is checked¶

    All settings are parsed once at start, against one schema. If anything is wrong, the process exits before it serves a request, with one line that names every problem:

    Invalid configuration — DATABASE_URL: must be a postgres:// connection string; SMTP_URL and SMTP_FROM must be set together

    A few rules apply throughout:

    • An empty value counts as unset for every optional variable, so SMTP_URL= is the same as leaving it out.
    • Lists are comma-separated. Spaces around items are trimmed, items are lowercased, and duplicates are dropped.
    • Some variables come in sets. Setting only part of a set, such as SMTP_URL without SMTP_FROM, is refused.
    • Set the same environment on every container. Web and worker containers read the same variables, and the migrate, create-admin and rotate-encryption-key commands read them too.

    Core¶

    Variable Default Required Meaning
    APP_ROLE all No What the container runs: all (console and jobs), web (console only) or worker (jobs only). See APP_ROLE.
    PORT 3000 No The HTTP port every role listens on, including worker, for its health checks. An integer from 1 to 65535.
    PUBLIC_URL http://localhost:3000 Yes, outside a local trial The address people reach the console at, such as https://sync.example.com. Must be a bare http(s) origin with no path, query or fragment. Must be https:// unless the host is localhost, *.localhost, 127.0.0.1 or [::1]. Sign-in redirects, the Salesforce callback and the change notifier's endpoint are built from it, and requests from other origins are rejected.
    ALLOW_INSECURE_PUBLIC_URL unset No true accepts a plain http:// PUBLIC_URL on a non-local host, for example on an isolated network. Session cookies can only be locked to the host over https, so use this only on a network you trust.
    LOG_LEVEL info No The lowest level written to stdout: fatal, error, warn, info, debug or trace. Opening the Live log raises it to debug for the Live log only, never for stdout.
    MIGRATE_ON_BOOT unset No true makes the container's serve command run the platform database migrations before it starts the app. Read by the image's entrypoint, not by the app. Convenient for a single container; with several containers, run migrate as a separate step.
    BUILD_COMMIT set at build time No The git commit the image was built from, shown shortened in the sidebar footer. A 7 to 40 character hex SHA. Normally passed as the BUILD_COMMIT build argument rather than set at run time.

    The image also sets NODE_ENV=production. You don't need to change it.

    Databases¶

    Variable Default Required Meaning
    DATABASE_URL none Yes The platform database: AlgoBridge's own users, connections, mappings, jobs and sync state. A postgres:// or postgresql:// URL. PostgreSQL 15 or later.
    CLIENT_DATABASE_URL unset No The client database, the one AlgoBridge syncs. When set, it wins over a connection saved on the Connections screen, and the screen refuses to save or disconnect. See below for the format.

    CLIENT_DATABASE_URL is checked at start with the same rules the Connections screen uses. It must:

    • start with postgres:// or postgresql://;
    • include a host, a user name, and exactly one database name after the host;
    • carry no query option other than sslmode, which must be one of disable, allow, prefer, require, verify-ca or verify-full.
    CLIENT_DATABASE_URL: postgres://app_user:change-me@db.example.com:5432/app?sslmode=require

    It must point at a different database from DATABASE_URL. A URL that points at the platform database is refused when the connection is checked.

    Warning

    Setting CLIENT_DATABASE_URL replaces a connection saved on the Connections screen the first time the connection is checked, and the saved URL cannot be recovered. If you unset the variable later, enter the URL in the console again.

    Encryption¶

    Variable Default Required Meaning
    ENCRYPTION_KEY unset Needed to connect Salesforce Encrypts the secrets AlgoBridge stores: Salesforce tokens and app credentials, a client database URL saved in the console, and two-step verification keys. Exactly 32 random bytes in base64: generate it with openssl rand -base64 32. The app starts without it, but saving a connection or turning on two-step verification is refused.
    ENCRYPTION_KEY_PREVIOUS unset No Only while rotating keys: the old key. It still decrypts, and never encrypts. Requires ENCRYPTION_KEY, and must differ from it.

    Rotating the encryption key¶

    Rotation has no downtime.

    1. Generate a new key with openssl rand -base64 32.
    2. On every container, move the current key to ENCRYPTION_KEY_PREVIOUS, put the new key in ENCRYPTION_KEY, and restart.

    3. Re-encrypt every stored secret with the new key:

      docker compose -f deploy/docker-compose.yml run --rm app rotate-encryption-key

      It prints Re-encrypted N stored secret(s) with key <id>. You can now remove ENCRYPTION_KEY_PREVIOUS. It runs in one transaction: if any value cannot be decrypted, nothing changes, and the command names the problem.

    4. Remove ENCRYPTION_KEY_PREVIOUS and restart.

    Salesforce¶

    Variable Default Required Meaning
    SALESFORCE_CLIENT_ID unset No The consumer key of the External Client App AlgoBridge signs in through.
    SALESFORCE_CLIENT_SECRET unset No The app's consumer secret.

    Set both or neither. When both are set, they win over credentials saved on the Connections screen, and the screen shows the app as Set by the deployment. When neither is set, an admin saves them on the Connections screen instead. The org itself is always connected from the console. See Salesforce connection.

    Sign-in and single sign-on¶

    By default, people sign in with an email and password, plus optional two-step verification. Single sign-on providers are added with AUTH_PROVIDERS; several can be active at once. See Single sign-on for the provider setup.

    General¶

    Variable Default Required Meaning
    AUTH_PROVIDERS local No Comma-separated sign-in methods: any of local, google, microsoft and oidc. Must include local unless AUTH_LOCAL_LOGIN=off. Each SSO provider listed needs its own settings below.
    AUTH_LOCAL_LOGIN all No Who may sign in with an AlgoBridge password: all, admins or off. admins is recommended once SSO works, keeping a break-glass path. off removes the password form and needs at least one SSO provider. create-admin and admin-issued set-password links work in every mode.
    AUTH_ALLOWED_DOMAINS empty No Comma-separated email domains, such as example.com, whose verified SSO users may sign up on first sign-in without an invite. New accounts start as viewer. When empty, every new user needs an invite.

    Google Workspace¶

    Required together when AUTH_PROVIDERS includes google.

    Variable Meaning
    GOOGLE_CLIENT_ID The OAuth client ID.
    GOOGLE_CLIENT_SECRET The OAuth client secret.
    GOOGLE_HOSTED_DOMAIN Your Workspace domain, such as example.com. Only accounts whose hosted domain matches it can sign in, so personal Gmail accounts are always refused.

    Microsoft Entra ID¶

    Required together when AUTH_PROVIDERS includes microsoft.

    Variable Meaning
    MICROSOFT_CLIENT_ID The application (client) ID.
    MICROSOFT_CLIENT_SECRET The client secret.
    MICROSOFT_TENANT_ID Your directory (tenant) ID, as a GUID. common, organizations and consumers are refused, because they would admit accounts from any tenant.

    Generic OIDC¶

    For Okta, Keycloak, Auth0 and other standard OpenID Connect providers. The first four are required together when AUTH_PROVIDERS includes oidc.

    Variable Required with oidc Meaning
    OIDC_ISSUER Yes The issuer URL. Must be https://. AlgoBridge reads the provider's endpoints from its discovery document.
    OIDC_CLIENT_ID Yes The client ID.
    OIDC_CLIENT_SECRET Yes The client secret.
    OIDC_DISPLAY_NAME Yes The provider name on the sign-in button, shown as "Continue with" followed by this name.
    OIDC_ALLOWED_EMAIL_DOMAINS No, recommended Comma-separated email domains the provider is trusted for. Checked on every sign-in that matches by email. When empty, any verified email the provider asserts is accepted, and only the invite list keeps out unwanted accounts.

    Domain lists match exactly: a subdomain of an allowed domain is not covered.

    Email¶

    Email is optional. Without it, invite and password-reset links are shown to the admin once, to copy and send, and alerts appear only in the console.

    Variable Default Required Meaning
    SMTP_URL unset No The SMTP relay, as an smtp:// or smtps:// URL, for example smtps://user:change-me@mail.example.com:465. Any provider's SMTP endpoint works.
    SMTP_FROM unset With SMTP_URL The sender, for example AlgoBridge <noreply@example.com>.

    Set both or neither.

    Alert mail uses the same SMTP_URL and SMTP_FROM. It goes to every active user whose role carries alerts.receive (admins, by default), plus any extra addresses entered on the Alerts screen, which also sends a test email. The resolved mail waits until the problem has stayed clear for 15 minutes, so a problem that clears and comes straight back does not send a burst of mail.

    Jobs and workers¶

    No environment variable tunes the job engine. Jobs live in the algobridge_jobs schema of the platform database named by DATABASE_URL, and the only job-related setting you choose per container is APP_ROLE. Sync behaviour such as poll intervals is set per mapping in the console. See Workers and jobs.

    Demo mode¶

    This version reads no demo setting. A demo instance is planned as the same image with a demo flag, but the feature is not built yet.

    Example¶

    A single-container install behind a TLS proxy, with Google sign-in and email:

    environment:
  DATABASE_URL: postgres://algobridge:change-me@db:5432/algobridge
  APP_ROLE: all
  MIGRATE_ON_BOOT: "true"
  PUBLIC_URL: https://sync.example.com
  ENCRYPTION_KEY: <openssl rand -base64 32>
  SMTP_URL: smtps://user:change-me@mail.example.com:465
  SMTP_FROM: AlgoBridge <noreply@example.com>
  AUTH_PROVIDERS: local,google
  AUTH_LOCAL_LOGIN: admins
  GOOGLE_CLIENT_ID: change-me
  GOOGLE_CLIENT_SECRET: change-me
  GOOGLE_HOSTED_DOMAIN: example.com
