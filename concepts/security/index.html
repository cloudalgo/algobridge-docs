    Security¶

    AlgoBridge holds credentials for your Salesforce org and your database, and it can change records in both. This page explains how it protects them: who can sign in, what each role can do, how every change is protected against forgery and double submission, how stored secrets are encrypted, and what data leaves your network.

    Sign-in¶

    AlgoBridge supports two ways to sign in. You can use both at once.

    Local accounts. Email and password, with optional two-step verification (TOTP). Passwords are hashed with argon2id. The first administrator is created from the command line with create-admin. Local accounts also serve as a break-glass route if your identity provider is unavailable.

    Single sign-on. One OpenID Connect adapter, with presets for Google Workspace and Microsoft Entra ID, and a generic option for any other OIDC provider. Several providers can be active at the same time. See Single sign-on.

    A few rules apply to every sign-in:

    • Identities are keyed by issuer and subject, never by email. Changing an email address at your provider cannot hand an account to someone else.
    • Invite-only by default. A person needs an invitation before they can sign in. To allow self sign-up through single sign-on, list your email domains in AUTH_ALLOWED_DOMAINS. A person with a verified email in one of those domains is created on first sign-in, as a viewer.
    • You decide who may use a password. AUTH_LOCAL_LOGIN is all (the default), admins (only administrators may sign in with a password) or off (single sign-on only).
    Limit Value
    Session lifetime 12 hours, absolute
    Idle timeout 2 hours
    Failed attempts before lockout 5
    Lockout 15 minutes
    Invite and password-reset links single use, valid for 7 days
    A started SSO sign-in must finish within 10 minutes

    Roles¶

    AlgoBridge has three roles. Permissions are defined in code, not edited in the console, so a role means the same thing on every instance.

    Role Can
    Viewer See sync status and errors.
    Member Everything a viewer can, plus retry failed records, operate sync, and create, edit and delete mappings.
    Admin Everything, including managing connections, users and settings, and viewing the Live log.

    Every route is denied unless it names the permission it needs, so a new screen cannot ship open by accident. AlgoBridge also refuses to remove or demote the last administrator. See Users and roles.

    Every write is forgery-checked and idempotent¶

    Every form that changes something carries two hidden values:

    • A signed form token (_csrf) proves the form came from AlgoBridge, for this session. The token is an HMAC-SHA256 signature, using a key stored in AlgoBridge's database, and it is bound to your session. A forged or missing token is refused. Scripts send it in the Algobridge-Form-Token header.
    • A one-time idempotency key (_idem) is issued fresh each time a form is shown. If the same form is submitted twice, for example by a double click or a browser retry, the action runs once.

    How a repeated submission is answered:

    Case Answer
    The first submission redirected The same redirect is sent again. Nothing runs twice.
    The first submission rendered a page 409. A rendered page may show a one-time secret, so it is never replayed.
    The first submission is still running 409.
    Same key, different form contents 422.

    Idempotency keys expire after 24 hours.

    Serve AlgoBridge over HTTPS

    Over HTTPS, AlgoBridge's cookies carry the __Host- prefix, which locks them to your exact origin. AlgoBridge refuses to start with a plain http:// PUBLIC_URL, unless the URL is on loopback or you set ALLOW_INSECURE_PUBLIC_URL=true. Use that setting only for local testing.

    Encryption of stored secrets¶

    Secrets AlgoBridge stores in its database are encrypted with AES-256-GCM under the key in ENCRYPTION_KEY (32 bytes, base64). This covers:

    • the client database connection string,
    • the Salesforce tokens and connected app secret,
    • the change notifier's secrets,
    • two-step verification keys.

    Each value records which key encrypted it, so AlgoBridge can tell old keys from new.

    Rotating the key¶

    1. Set the new key in ENCRYPTION_KEY and the old one in ENCRYPTION_KEY_PREVIOUS.
    2. Run the rotate-encryption-key command. It re-encrypts every stored secret under the new key in one transaction.
    3. Remove ENCRYPTION_KEY_PREVIOUS.

    See Configuration.

    Keep the key safe

    Without ENCRYPTION_KEY, the stored secrets cannot be decrypted. Store it in your secret manager or platform configuration, never in the image or in source control.

    The Salesforce connection¶

    AlgoBridge connects to Salesforce through an External Client App that you create in your org, using OAuth with PKCE. It connects only to your org's My Domain (*.my.salesforce.com). Disconnecting revokes the token in Salesforce. Use a dedicated integration user, so you control exactly what AlgoBridge can see and change. See Salesforce connection.

    Notifier request signing¶

    When you use the change notifier, Salesforce sends requests to AlgoBridge. Every request is signed with HMAC-SHA256 under a secret shared at pairing. AlgoBridge checks the key, the signature, the org, a timestamp within five minutes and a nonce it has not seen before. It also limits body size, the number of object names and the request rate. A refused request gets an empty answer, so a caller learns nothing about why it failed. Repeated refusals open an alert.

    A notification carries only object API names, never record data. The worst a stolen secret allows is triggering early fetches, which the governor still bounds. The Change notifier page lists every check and covers key rotation and revocation.

    What data leaves your network¶

    Traffic Direction What it carries
    Salesforce API calls outbound HTTPS Queries and writes for the objects and fields you map.
    Change notifications inbound, from your Salesforce org Object API names only, and only if you use the notifier.
    Email outbound SMTP Invitation and password-reset links, and only if you configure SMTP. Without SMTP, the links are shown to the administrator instead.

    Nothing else leaves. AlgoBridge has no telemetry and makes no calls to its maintainers.

    Logs go to standard output and never carry field values or Salesforce error text. Salesforce error messages can quote the values you sent, so they are stored with the change and shown only on the authenticated Activity screen.

    Not yet built¶

    These features are planned and are not in the current build:

    • mutual TLS and an IP allow-list for the notifier endpoint,
    • an audit log of console actions,
    • the /api/v1 API and its access tokens,
    • outgoing webhooks.
