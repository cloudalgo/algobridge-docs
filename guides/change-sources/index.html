    Choose a change source¶

    This guide helps you pick how AlgoBridge learns that records changed in Salesforce, and switch to that source. The three sources differ in what you install in the org, in how many API requests they spend, and in how quickly a change arrives.

    Every source ends in the same place: when an object has changed, AlgoBridge reads the changed records with a paged SOQL query. The source only decides how AlgoBridge finds out which objects to read. See Salesforce to PostgreSQL.

    Before you start¶

    • Salesforce is connected.
    • For the Apex probe or the change notifier: an admin who can deploy Apex to the org.
    • For the change notifier: PUBLIC_URL is an https:// address that Salesforce can reach.

    Compare the sources¶

    Composite polling Apex probe Change notifier
    Installs in your org Nothing The AlgoBridge Apex bundle The same bundle, plus two Flows per synced object
    How it learns about changes Asks Salesforce on each poll whether each object changed Asks one class in your org, which checks up to 90 objects per request Your org tells AlgoBridge which objects changed, as it happens
    Requests per poll One per five objects One for up to 90 objects None; one fallback poll an hour
    Latency The poll interval The poll interval Near real time
    Needs inbound HTTPS to AlgoBridge No No Yes

    Composite polling is the default.

    What each one costs¶

    Daily API requests for 50 synced objects. The range covers poll intervals from 2 to 30 minutes.

    Source Requests per day At a 5 minute interval
    Composite polling about 480 to 7,200 about 2,900
    Apex probe about 48 to 720 about 290
    Change notifier 0 to learn about changes, plus the fallback poll and 1 daily check about 25 with the Apex probe as fallback

    The change notifier's fallback poll runs once an hour by default. It uses the Apex probe (24 requests a day) when the bundle is installed, or Composite polling (240 a day at 50 objects) otherwise. The notifier also uses one asynchronous Apex execution in your org per transaction that saves a synced object, from the org's daily allowance (the larger of 250,000 or 200 per user licence).

    When the org nears its API limit, the budget governor widens every interval by four times, up to an hour, and Composite polling is the first to feel it. See API budget.

    When to pick each¶

    • Composite polling if you can't deploy Apex, or you're trying AlgoBridge out. It works everywhere and needs no inbound access.
    • Apex probe for most production orgs. One deploy cuts polling requests by about ten times, needs no per-object setup, and nothing calls into AlgoBridge.
    • Change notifier when you need changes within seconds, or need the lowest API use, and AlgoBridge can accept HTTPS requests from Salesforce. You add two Flows by hand for each synced object.

    Switch the change source¶

    1. Open Instance → Connections and scroll to Change detection.
    2. Read the three cards. Each lists what it installs, what it costs, its benefits and its limitations. The selected card is marked Selected.
    3. For the Apex probe or the change notifier, install the bundle: click Deploy bundle, then assign the permission set. See Install the Apex bundle.
    4. For the change notifier, click Pair notifier and add the Flows. See Pair the change notifier.
    5. Click Use this source on the card you want.

    AlgoBridge verifies the source before saving it:

    • Composite polling has nothing to verify.
    • Apex probe makes one status call and checks that the bundle reports the expected version with the probe enabled.
    • Change notifier makes the same status call and checks that the notifier is installed and paired, that PUBLIC_URL uses https, and that this instance holds a live key.

    If the check passes you see Change source saved. If not, Nothing was saved. The change source stays as it was. with the reason.

    Card states¶

    State Meaning
    Nothing to verify Composite polling.
    Verified 09:12 The last check passed at that time.
    Not verified yet No check has run since the source was chosen.
    Not installed: deploy the bundle The bundle is missing or too old.
    Not paired The notifier has no live key.
    Paired, key abk_…, last notification 12:40 The notifier is working.

    How a failing source is handled¶

    A daily job checks the selected source at 02:20 UTC for one API request. If the source has become unusable, for example because someone deleted the Apex classes, AlgoBridge:

    • keeps polling with the next source down (change notifier, then Apex probe, then Composite polling),
    • opens the sf_change_source alert,
    • shows on Connections, for example: Selected: Apex probe. Unavailable since 12:40: … Running on Composite.

    AlgoBridge never changes your selection by itself. Fix the cause, then click Use this source again to verify it.

    Watch it in the Live log¶

    These events appear in the Live log: sf_change_source_selected, sf_change_source_refused, sf_change_source_checked, and for the notifier notifier_paired, notifier_pair_failed, notifier_key_rotated, notifier_key_revoked, notifier_notification_accepted, notifier_notification_rejected and notifier_notification_not_selected.

    Troubleshooting¶

    Not installed: deploy the bundle

    The status call found no bundle, or a bundle older than the one this release expects. Click Deploy bundle. See Install the Apex bundle.

    The Apex probe reports an object as failed

    The probe runs as the integration user, with sharing, in user mode. An object the integration user can't read is reported as failed. Give the user read access to the object, and check the AlgoBridge Integration permission set is assigned.

    AlgoBridge must be reachable over HTTPS: set PUBLIC_URL to an https:// address.

    The change notifier needs Salesforce to call AlgoBridge. Put AlgoBridge behind HTTPS, set PUBLIC_URL to that address, restart, and redeploy the bundle so its remote site matches.

    This instance holds no live notifier key; pair the notifier again

    The notifier keys were revoked or deleted, for example by disconnecting Salesforce. Click Pair notifier, then Use this source.

    Changes made by the integration user don't arrive quickly

    The change notifier ignores saves made by the integration user, so AlgoBridge's own writes don't echo back. Changes made under that user arrive on the hourly fallback poll instead. Use a dedicated integration user that people don't sign in as.
