    Connect Salesforce¶

    This guide connects your instance to one Salesforce org. You create an External Client App in Salesforce, give AlgoBridge its credentials, and sign in once as the integration user. After that, AlgoBridge refreshes its own tokens.

    An instance connects exactly one org. To sync a second org, run a second instance.

    Before you start¶

    • ENCRYPTION_KEY is set on every container (web and worker). AlgoBridge stores the OAuth tokens, and any app credentials saved on screen, encrypted with this key. Generate one with openssl rand -base64 32. See Configuration.
    • PUBLIC_URL is set to the address your browser uses to reach the console, for example https://sync.example.com. The OAuth callback is built from it.
    • You have a dedicated integration user in Salesforce. AlgoBridge signs in as this user and every call it makes runs as them. A dedicated user keeps the audit trail clear and matters later if you use the change notifier, which ignores the integration user's own saves.
    • You can create apps in Setup in the org.

    Choose where the app credentials live¶

    The app's consumer key and secret can come from the console or from the deployment.

    Connections screen Environment variables
    Where they're stored Encrypted in the platform database Your deployment's secret store
    How to change them Replace on screen Change the variables and restart
    Shown on screen as Saved on this screen Set by the deployment (SALESFORCE_CLIENT_ID)

    If both are set, the environment variables win.

    Step 1: Create the External Client App¶

    1. In Salesforce, open Setup → External Client App Manager and create a new app.
    2. Name it AlgoBridge and enter a contact email.
    3. Turn on Enable OAuth.

    4. Set the Callback URL to your PUBLIC_URL followed by /connections/salesforce/callback, for example:

      https://sync.example.com/connections/salesforce/callback

      The Connections screen shows this exact URL with a Copy button.

    5. Add these OAuth scopes:

      • Manage user data via APIs (api)
      • Perform requests at any time (refresh_token, offline_access)
    6. Turn on Require PKCE.
    7. Leave Require secret for Web Server Flow on.
    8. Set the refresh token policy to valid until revoked. Rotating refresh tokens also works: AlgoBridge refreshes under a database row lock, so two processes never race for the same token.
    9. Save the app, then copy its Consumer Key and Consumer Secret.

    Note

    A new app can take a few minutes before Salesforce accepts sign-ins to it. If the first connect fails with a credentials error, wait and try again.

    Step 2: Give AlgoBridge the app credentials¶

    1. In the console, open Instance → Connections.
    2. In the Salesforce panel, paste the Consumer key and Consumer secret.
    3. Click Save app credentials.

    The secret is stored encrypted and never shown again. To change it later, click Replace. Remove app credentials is available only after you disconnect the org.

    1. Set both variables in your deployment's secret store:

      SALESFORCE_CLIENT_ID=change-me
SALESFORCE_CLIENT_SECRET=change-me

      Set them together. The app refuses to start if only one is set.

    2. Restart every container.

    The panel now reads Set by the deployment (SALESFORCE_CLIENT_ID). To use a different app, change both variables and restart.

    Step 3: Connect the org¶

    1. In the Salesforce panel, enter your My Domain URL:
      • Production: https://yourcompany.my.salesforce.com
      • Sandbox: https://yourcompany--sandbox.sandbox.my.salesforce.com
    2. Click Connect to Salesforce.
    3. Salesforce opens. Sign in as the integration user and allow access.
    4. You return to Connections with the notice Salesforce connected. Tokens are stored encrypted.

    The panel now shows the org, its My Domain and org ID, the user AlgoBridge runs as, the instance, the API version, when tokens were last refreshed, and API usage today.

    API cost

    Token requests, token revokes and identity lookups don't count against the org's daily API limit. Check connection costs one API call: it reads the org's record and the current usage that Salesforce reports with the response. See API budget.

    Check the connection¶

    Click Check connection at any time to confirm the tokens still work and to refresh the usage figures. The panel stamp shows one of these states:

    Stamp Meaning
    Not connected No org is connected yet.
    Connected The tokens work.
    App changed The app credentials changed after the org was authorized. Reconnect to issue tokens to the new app.
    Reconnect needed Salesforce refused the stored tokens.

    Reconnect when authentication fails¶

    Salesforce stops accepting the refresh token when it is revoked, when it expires under the app's policy, or when you change the app credentials. Sync then stops with an authentication error and the panel shows Reconnect needed or App changed.

    1. Open Instance → Connections.
    2. Click Reconnect in the Salesforce panel.
    3. Sign in as the same integration user, in the same org, and allow access.

    You see Salesforce reconnected. New tokens are stored encrypted. Your mappings, and a paired change notifier, are kept, because the org is the same.

    AlgoBridge refuses a reconnect that signs in to a different org. To change orgs, disconnect first.

    Disconnect¶

    1. Delete your mappings. Disconnect is refused while any exist.
    2. Click Disconnect, then Disconnect Salesforce in the dialog.

    AlgoBridge revokes the refresh token in Salesforce and deletes both stored tokens. Any change notifier keys are deleted too, so you must pair again after connecting.

    Troubleshooting¶

    Salesforce shows redirect_uri_mismatch

    The callback URL in the app doesn't match the one AlgoBridge sends. Copy the URL from the Connections screen into the app exactly. It must use https and have no trailing slash. Check that PUBLIC_URL matches the address you use in the browser.

    Salesforce rejected the consumer key or secret.

    The key or secret is wrong, or the app is not usable yet. Copy both again from the app, click Replace, and wait a few minutes if the app is new.

    The app must allow the refresh_token scope

    Add Perform requests at any time (refresh_token, offline_access) to the app's OAuth scopes and connect again.

    This connect link expired. Start again.

    More than 10 minutes passed between clicking Connect to Salesforce and returning, or the link was already used. Click the button again.

    You signed in to a different org. Disconnect first to change orgs.

    You signed in to an org other than the connected one. Sign in to the original org, or delete your mappings, disconnect and connect the new org.

    Delete your mappings first.

    Disconnect is refused while mappings exist. Delete them on Sync → Mappings, then disconnect.

    Could not reach Salesforce.

    The container has no outbound HTTPS route to Salesforce, or Salesforce is unavailable. Check outbound network access and try again.

    Salesforce disconnected, but Salesforce didn't confirm the revoke

    AlgoBridge deleted its tokens, but Salesforce didn't confirm the revoke. Revoke the token by hand in Setup → Connected Apps OAuth Usage.

    The connection changed while you were confirming. Check it and try again.

    Someone else changed the connection while your dialog was open. Reload the page and repeat the action.
