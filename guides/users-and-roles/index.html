    Manage users and roles¶

    This guide shows you how to create the first admin, invite people, give each one the right role, and handle lost passwords and authenticators.

    Each person has exactly one role. Roles are fixed: there is no role editor.

    Before you start¶

    • The platform database is migrated. See Install.
    • To email invitations, set SMTP_URL (smtp:// or smtps://) and SMTP_FROM together. Without them, AlgoBridge shows each link to the admin once, to pass on yourself.
    • If people will sign in through SSO, set that up first. See Set up sign-in.

    Roles and what they allow¶

    Role Can
    viewer See sync status, mappings, activity and errors, and the Jobs & workers page.
    member Everything a viewer can, plus create, edit and delete mappings, retry failed records, and operate sync (retry, cancel, redrive and dismiss jobs).
    admin Everything, including connections, users and the Live log.

    The permissions behind each role:

    Permission viewer member admin
    sync.view ✓ ✓ ✓
    errors.view ✓ ✓ ✓
    records.retry ✓ ✓
    sync.operate ✓ ✓
    mappings.manage ✓ ✓
    mappings.delete ✓ ✓
    connections.manage ✓
    users.manage ✓
    settings.manage ✓
    logs.view ✓
    alerts.receive ✓
    webhooks.manage ✓
    tokens.manage ✓
    audit.view ✓

    Pages a person can't use are hidden from their navigation.

    Create the first admin¶

    The first admin is created from the command line, on the server.

    1. Run the migrations, if you haven't:

      docker compose -f deploy/docker-compose.yml run --rm app migrate

    2. Create the admin:

      docker compose -f deploy/docker-compose.yml run --rm app create-admin --email you@example.com --name "Your Name"

      Outside Docker, run node dist/cli/create-admin.js with the same options.

    3. The command prints a set-password link once. Open it, choose a password, and sign in.

    The link works once and expires in 7 days.

    Invite a person¶

    1. Open Instance → Users and click Invite person.
    2. Enter their Email, optionally their Name, and choose a Role.
    3. Click Create invite link.

    What happens next depends on how they sign in:

    • Password sign-in: they get a set-password link that works once and expires in 7 days. With SMTP set, it is emailed: Invitation emailed. The link works once and expires in 7 days. Without SMTP, the page shows the link with Copy link. It isn't shown again.
    • SSO: they click their provider's button. AlgoBridge matches the invite by verified email.

    Invited users show as Invited until they accept. If the link expires, the row shows Link expired: click New link.

    Change a role¶

    Click Change next to the person's role, pick the new role, and save.

    You can't change your own role. Another admin has to.

    Reset a password¶

    There is no self-service "forgot password". To reset one:

    1. On Instance → Users, click Reset link for the person.
    2. Send them the link, or let SMTP email it.

    The link works once and expires in 7 days. A disabled user can't get a link until you enable them.

    Turn off two-step verification for someone¶

    If a person loses their authenticator:

    1. Click Turn off two-step on their row.
    2. Confirm with Turn off.

    They are signed out everywhere, any outstanding links are revoked, and they sign in with their password alone. They can set two-step verification up again from Account. This isn't offered for SSO users, who don't use AlgoBridge codes.

    Disable and enable users¶

    Click Disable to stop a person signing in. Their sessions end immediately. Users are never deleted.

    Click Enable to let them back in. If they never set a password, send them a new link.

    Rules that protect access¶

    • You can't change your own role or disable yourself.
    • The last active admin can't be demoted or disabled. Make another user an admin first.
    • The create-admin command works in every sign-in mode, so you can always recover access. If you're locked out, create another admin with a new email address.

    Troubleshooting¶

    This is the last active admin. Make another user an admin first.

    Promote someone else to admin, then change or disable this account.

    You cannot change your own role or status. Ask another admin.

    Ask another admin, or create one with create-admin.

    This person has not accepted their invitation yet. Send them a new link instead.

    The person hasn't set a password yet, so there's nothing to reset. Click New link.

    A disabled user cannot get a set-password link. Enable them first.

    Click Enable, then send the link.

    Link not valid

    Password links work once and expire after 7 days. Ask an admin for a new one.
