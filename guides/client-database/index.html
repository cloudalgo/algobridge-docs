    Connect the client database¶

    This guide connects your instance to the PostgreSQL database your application uses, the one AlgoBridge syncs with Salesforce. It also covers the privileges the database role needs, how the stored URL is protected, and how to rotate the encryption key.

    The client database is separate from AlgoBridge's own platform database (DATABASE_URL), which holds the console's state and the job queue. An instance connects exactly one client database.

    Before you start¶

    • PostgreSQL 15 or later, reachable from every container.
    • A database role for AlgoBridge with the privileges listed below.
    • Either ENCRYPTION_KEY set on every container, if you'll save the URL on screen, or access to set CLIENT_DATABASE_URL in your deployment.

    Required privileges¶

    AlgoBridge creates its tables, trigger function and change log in a target schema (algobridge by default) when you apply a mapping. The role in the URL needs to:

    • Use the hstore extension. Either the extension is already installed in the database, or the role can create it.
    • Own the target schema, or be able to create it. On the first apply, the schema must contain no tables, views or other relations.

    If a privilege is missing, the apply fails with a configuration error that names the missing grant. Nothing is changed in the database.

    Choose where the URL lives¶

    Connections screen CLIENT_DATABASE_URL
    Needs ENCRYPTION_KEY Yes No
    Restart to change No Yes
    Shown on screen as Connected on this screen Set by the deployment (CLIENT_DATABASE_URL)

    If CLIENT_DATABASE_URL is set, it wins. The screen can't save or disconnect a connection set by the deployment.

    Warning

    Setting CLIENT_DATABASE_URL on an instance that already has a URL saved on screen replaces the saved URL on the first check. The saved URL can't be recovered.

    Connect the database¶

    1. Make sure ENCRYPTION_KEY is set on every container. Generate one with:

      openssl rand -base64 32

    2. Open Instance → Connections.

    3. In the PostgreSQL panel, enter the Connection URL, for example:

      postgres://app_user:change-me@db.example.com:5432/app?sslmode=require

    4. Click Test and connect.

    AlgoBridge connects with a 5 second timeout and runs SELECT version(). If that works, it stores the URL encrypted and shows PostgreSQL connected. The URL was tested, then stored encrypted. If it fails, nothing is saved, and the error never contains the password.

    1. Set the URL in your deployment's secret store:

      CLIENT_DATABASE_URL=postgres://app_user:change-me@db.example.com:5432/app?sslmode=require

    2. Restart every container.

    The panel reads Set by the deployment (CLIENT_DATABASE_URL). To use a different database, change the variable and restart.

    After connecting, the panel shows only the host, port, database, user and SSL mode. The full URL is never shown again.

    Choose an SSL mode¶

    Set sslmode in the URL:

    sslmode Effect
    require Encrypts the connection.
    verify-full Encrypts, and also checks the server certificate and host name.
    not set No SSL. The panel shows Driver default.

    Use verify-full when the server has a certificate your containers trust.

    Check the connection¶

    Click Check connection to test the stored URL on demand. Each worker also checks it when it starts. The stamp shows:

    Stamp Meaning
    Not checked No check has run yet.
    Healthy The last check connected.
    Unreachable The host could not be reached.
    Refused The server refused the login or the database.

    Replace the URL¶

    1. In the PostgreSQL panel, enter the whole new URL in Replace with a new connection URL. You can't edit one part of the stored URL.
    2. Click Test and replace.

    Your mappings are kept. The new database is tested first, and the stored URL changes only if the test passes.

    Disconnect¶

    1. Delete your mappings. Disconnect is refused while any exist.
    2. Click Disconnect, then Disconnect PostgreSQL in the dialog.

    The stored URL is deleted and sync stops. Your tables and data stay in the database.

    Rotate the encryption key¶

    ENCRYPTION_KEY protects every secret AlgoBridge stores: the client database URL, the Salesforce tokens, app credentials saved on screen, and change notifier secrets. To rotate it without losing any of them:

    1. Generate a new key:

      openssl rand -base64 32

    2. On every container, move the current key to ENCRYPTION_KEY_PREVIOUS and put the new key in ENCRYPTION_KEY. Restart. AlgoBridge can now read secrets written with either key.

    3. Re-encrypt the stored secrets with the new key:

      docker compose -f deploy/docker-compose.yml run --rm app rotate-encryption-key

      Outside Docker, run node dist/cli/rotate-encryption-key.js. The command re-encrypts everything in one transaction and prints:

      Re-encrypted N stored secret(s) with key <id>. You can now remove ENCRYPTION_KEY_PREVIOUS.

      The key id is the first 8 hex characters of the key's SHA-256 hash, so you can tell keys apart without printing them.

    4. Remove ENCRYPTION_KEY_PREVIOUS from every container and restart.

    ENCRYPTION_KEY_PREVIOUS is refused at startup unless ENCRYPTION_KEY is also set, and the two must differ.

    Deleting rows in synced tables¶

    AlgoBridge doesn't sync TRUNCATE. Truncating a read-write table deletes nothing in Salesforce. It also clears the algobridge_lastop and algobridge_err status columns. To delete records in Salesforce from PostgreSQL, use DELETE, in batches for large sets.

    Troubleshooting¶

    This is AlgoBridge's own database. Connect your application's database instead.

    The URL points at the platform database, which holds the algobridge_jobs schema and the algobridge_migrations table. Use the URL of your application's database.

    Set ENCRYPTION_KEY to store a connection.

    Saving on screen needs an encryption key. Set ENCRYPTION_KEY on every container and restart, or set CLIENT_DATABASE_URL instead.

    Enter a URL like postgres://user:password@host:5432/database.

    The URL could not be parsed. Check the scheme, and percent-encode special characters in the password.

    AlgoBridge could not connect with this URL.

    The test connection failed within 5 seconds. Check the host, port, firewall rules, credentials and SSL mode from inside a container. Nothing was saved.

    CLIENT_DATABASE_URL sets this connection. Change it in the deployment.

    The deployment sets the URL, so the screen can't change it. Edit the variable and restart.

    Delete your mappings first.

    Disconnect is refused while mappings exist. Delete them on Sync → Mappings first.

    Apply fails with a missing privilege

    The role can't create the hstore extension, or doesn't own the target schema, or the schema already holds other relations on the first apply. Grant what the message names, or install hstore as a superuser, then apply again.
