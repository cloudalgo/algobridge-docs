    Frequently asked questions¶

    The product¶

    What is AlgoBridge?

    AlgoBridge keeps Salesforce objects and PostgreSQL tables in step, in both directions. Changes in Salesforce are copied to your tables. Rows you insert, update or delete in a read-write table are sent back to Salesforce. Your application works with plain SQL and never calls the Salesforce API itself.

    It does the job of a hosted Salesforce sync service, but you run it yourself as one container image, next to your own PostgreSQL, with no licence fee and no per-row charge.

    Is it really free?

    Yes. AlgoBridge is open source and self-hosted. You can run it in production without paying anyone. If you want help, CloudAlgo offers paid consulting and support: book a consultation or see Pricing.

    Is AlgoBridge released?

    Not yet. Version 2 is in active development. The core of the sync is built in both directions, but some features, such as alerts screens, webhooks and the API, are still to come. See Release notes for what exists today.

    How is it different from a hosted sync service?

    The main differences:

    • Cost. Hosted sync services are usually priced by the number of rows you sync. AlgoBridge has no licence fee and no per-row charge; you pay only for the container and database you already run.
    • Hosting. You run AlgoBridge on your own infrastructure, on any platform that runs containers, rather than on one vendor's platform.
    • Your data stays with you. Sync state lives in a PostgreSQL database you own, not in someone else's service.
    • API limits. Some hosted services make calls that do not count toward your org's API limits. AlgoBridge's calls do, like any integration you run yourself, so it is built to spend as few as possible. See API budget.
    • Change detection from Salesforce. AlgoBridge polls with SOQL, cheaply, or uses an optional notifier that Salesforce calls when records change.
    • Licence. AlgoBridge is open source.

    Setup and running¶

    What do I need to run it?

    Three things: a container runtime that keeps the container running, PostgreSQL 15 or later, and outbound HTTPS to Salesforce. AlgoBridge needs no Redis, message broker or shared disk. See Install.

    Does AlgoBridge need its own database?

    Yes. AlgoBridge keeps its own data, such as users, mappings, jobs and watermarks, in a database of its own. Your synced tables live in your client database. The two must be different databases, though they can share a PostgreSQL server. AlgoBridge refuses to use its own database as the client database. See Architecture.

    Can one instance sync several Salesforce orgs or databases?

    No. One instance syncs exactly one Salesforce org with exactly one client database. To sync another pair, run another instance. This keeps every setting, job and alert unambiguous.

    Can I run more than one container?

    Yes. The same image runs as APP_ROLE=web (console only), worker (sync only) or all (both). Workers coordinate through PostgreSQL, so you can run several and any one can take over from another. See Workers and jobs.

    What does AlgoBridge change in my database?

    It creates your mapped tables and a small set of objects in one schema, algobridge by default: a change log, its archive, a capture trigger on each read-write table, and a few status columns. Everything it creates carries the algobridge_ prefix. It never drops or recreates a table, and every schema change is shown to you as a diff before you apply it. See Client database.

    Sync behaviour¶

    How does AlgoBridge learn about changes in Salesforce?

    By polling with SOQL, in two steps. A cheap probe first asks whether an object has changed since the last pass. Only if it has does AlgoBridge fetch the changed records. You can also install an Apex bundle that answers the probe for up to 90 objects in one call. Or you can use the change notifier, which lets Salesforce tell AlgoBridge which objects changed at no API cost. See Change sources.

    Does AlgoBridge use Change Data Capture or streaming events?

    No. Salesforce Change Data Capture is not used at all. Detection is SOQL polling, optionally sped up by the change notifier, and a daily reconciliation sweep catches anything polling misses.

    How quickly do changes appear?

    From PostgreSQL to Salesforce, a change is sent when 200 changes are waiting, or when the oldest has waited the maximum wait: 60 seconds by default, adjustable from 10 to 900. From Salesforce to PostgreSQL, it depends on the poll interval: 5 minutes by default for a busy object, backing off to 30 minutes for a quiet one. With the change notifier, a fetch starts as soon as Salesforce sends its notification. The governor slows everything down if your org's API usage gets high.

    How many Salesforce API calls will it use?

    It depends on how many objects you map, how often they change, and which change source you use. As a guide, detection for 50 objects polled every 5 minutes costs about 2,900 calls a day with the default Composite probe, about 290 with the Apex probe, and about 25 with the change notifier. Fetches and writes come on top. API budget shows how to estimate your own total.

    What happens if both sides change the same record?

    Each read-write mapping has a conflict policy: sf_wins (the default), pg_wins or latest_wins. A conflict exists only while a PostgreSQL change for the record is still waiting to be sent. See Conflicts.

    What happens when Salesforce rejects a change?

    AlgoBridge retries it, with growing delays, up to 5 times. If it still fails, the change is parked as failed and shown on the Activity screen with Salesforce's error message. From there you can retry it or discard it. A failure on one record holds back only that record and any children that refer to it; everything else keeps syncing. See PostgreSQL to Salesforce.

    Are formula fields synced?

    No. Salesforce does not update a record's SystemModstamp when only a formula's inputs change, so polling could never keep a formula value correct. The mapping editor shows formula fields as not synced.

    Security¶

    Does any of my data leave my network?

    Only what Salesforce sync needs: AlgoBridge calls Salesforce for the objects and fields you map. If you use the change notifier, Salesforce sends AlgoBridge object names, never record data. If you configure SMTP, invitation and reset emails go through your mail server. AlgoBridge sends no telemetry. See Security.

    How do people sign in?

    With a local email and password, optionally with two-step verification, or through single sign-on with Google Workspace, Microsoft Entra ID or any OpenID Connect provider. Access is invite-only by default, and there are three roles: viewer, member and admin. See Single sign-on and Users and roles.
